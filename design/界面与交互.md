# 界面与交互（主界面 HUD / 角色页面）

> **本文件负责**：主界面骨架、右上角操作区、左侧导航、单工作页、角色页面的布局与交互口径。
> **不在本文件**：角色名单与社交恩赐 → `角色与抽卡.md`；装备的属性与栏位 → `资源表.md` 各时代的「装备与武器」小节；七套被动 / 角色上限与上场机制 / 图鉴 / 招募 / 仓库 → `被动.md`。

## 一、主界面 HUD

| 元素 | 规则 |
|---|---|
| 位置 | **最左上角** |
| 内容 | **玩家头像 + 玩家名字**（头像在左、名字在右）；**名字下面不标时代** |
| 默认头像 | **空白头像**（占位剪影） |
| 头像自定义 | ① 自行上传 / 选择；② 使用已解锁的「角色头像」（素材见 `角色与抽卡.md「卡池角色（2 位英雄 + 随机普通角色）」`）|
| 角色头像解锁 | 该角色**好感度 ≥ 25%** 即解锁其头像使用权，好感不足之前不显示（见 `角色与抽卡.md「好感度系统」`） |
| 玩家名字 | **第一次进入游戏时创建**；**随时点击名字即可免费改名** |
| 版本号 | 时代徽章右边常驻 **测试版版本号**`v0.0.x`（如 `v0.0.3`），只读，方便反馈问题时对版本 |
| 头像尺寸 | 上传源统一 **256 × 256 正方形**：上传后等比缩放 + 居中裁剪；格式 PNG / JPG / WebP，≤ 2 MB。**显示尺寸不写死**，随角色格大小自动缩放（见 §5.3） |

**为什么默认空白**：空白头像本身就是「这里该有你的东西」的提示，比塞一个通用剪影更能推动玩家去设置。

### 1.1 顶栏资源条（不占格资源的唯一常驻位置）

顶栏**左侧、标题与版本号的右边**常驻一条资源条（其余空间把右侧操作按钮推到底），**只放这 4 项**：

| 项 | 显示 | 点击去哪 |
|---|---|---|
| **金币** | 当前金币 | `#商店` |
| **科研点** | 当前科研点（**第一次攒到 ≥1 才出现**）| 「科研 · 科技树」页 |
| **电力** | **当前电量 / 上限**（**第一次产出 ≥1 瓦才出现**）| 电力工作页 |
| **食物** | **粮仓当前份数**（与粮仓标签**同一个数**，实时同步；撑不到 1 分钟时变红），右侧再显示**每秒消耗**`-0.05×上场人数/秒` | `#仓库` 的粮仓标签 |

- **食物就是粮仓的那条数**：资源条的食物 = 粮仓当前份数，**不做第二套统计** —— 粮仓里被吃掉、腐坏掉，资源条同步往下走。
- **科研点 / 电力按需出现**：第一次达到 **≥1** 时才出现在资源条上；之后即使花到 0 / 掉到 0 **也不消失**（避免界面元素闪进闪出）。
- **金币与食物常驻**：金币开局为 0 也显示，食物从有粮仓起就显示。
- **占仓库格的物品一律不进资源条** —— 它们是物品，只在 `#仓库` 页出现；资源条里只有「数值」。
- 星尘、英雄碎片这些**是物品**（占格），也不常驻，分别去商店 / 招募看。
- 资源条与左侧导航的实时小字**分工不同**：资源条回答「我现在有多少」，导航小字回答「这一项进展到哪」。

## 二、右上角操作区

HUD 右上角固定四个按钮（**它们的左边是资源条**，见 §1.1）：

| 按钮 | 作用 |
|---|---|
| **设置** | 打开设置弹窗：**主题（深色 / 浅色，立即生效并写进存档）**、立即存档、导出、导入、**重新开始（清空存档 → 回到起名页；二次确认，提示不可恢复）** |
| **存档** | 立即写一次 localStorage（平时 15 秒自动存一次，切后台 / 关页面也会存） |
| **导出** | 把存档复制到剪贴板（base64，粘到记事本即备份；重开前建议先点它） |
| **导入** | 粘贴一段存档覆盖当前进度，成功即自动刷新 |

## 三、主界面栏位分类与左侧导航

### 3.1 三个栏位

| 栏位 | 装什么 | 数量 |
|---|---|---|
| **工作** | 常规工作（伐木 … 曲速核心制造） | **31 份** |
| **被动** | 住所与娱乐 / 防御 / 商店 / 角色 / 图鉴 / 招募 / **仓库** | **7 套** |
| **角色特技** | 社交恩赐生成的工作：#黑暗之魂 / #模拟纪元 | **2 份** |

- **角色特技与被动明确分隔**：它既不是「人人可做的工作」，也不是「不需要入驻的被动」—— 它是**某个角色专属的工作**，所以单列一栏。
- 33 份工作的归属 = 31（工作栏）+ 2（角色特技栏），**两栏相加才是全部工作**。
- **没有「战斗」栏**：战斗只在 狩猎 / #黑暗之魂 / #模拟纪元 中进行 —— 它们分别是「工作」栏里的一份工作和「角色特技」栏里的两份工作。**袭击并入被动 #防御**，只做「基地战力 vs 袭击强度」的纯数值判定（见 `被动.md「袭击模型」`）。


### 3.2 左侧导航（照梅尔沃放置，逐项直接列出）

左侧栏不是图标按钮，而是**分组 + 逐项列出**（点哪一项，就打开那一项自己的页面）：

| 分组 | 列出什么 |
|---|---|
| 角色特技 | #黑暗之魂（星见由岐）/ #模拟纪元（大少）—— 好感 50 解锁后才出现 |
| 被动 | 住所与娱乐 · 防御 · 商店 · 角色 · 图鉴 · 招募 · **仓库**（逐项列出，每项带实时小字：人口 / 战力 / 金币 / 角色数 / 图鉴完成度 / 碎片数 / **已占格**） |
| 工作 | 31 份常规工作**逐项列出**（含 **科研**；**不显示时代、不按时代分组**；没被科技点名的工作完全不出现在列表里）。科研工作页**下方固定接整棵科技树**（已研究数 / 42 显示在页面头部） |

- 每一项右侧小字 = **`N人在工作`**（绿色）；没人入驻写「未入驻」。
- **工作不显示时代**：列表与工作页都不标时代 —— 时代只体现在科技树与物品上。
- 两份恩赐工作**只出现在「角色特技」一组**；狩猎作为常规工作留在「工作」组，不再有「战斗」入口。
- **电力是一项工作，不是被动**：科技解锁后左侧「工作」组里出现「电力」，发电设备（蒸汽 / 风力 / 太阳能 / 核电站）就在那一页建造；被动里只剩「防御」。

## 四、单工作页（梅尔沃技能页布局）

> **科研是例外**：科研工作页下方固定接一整棵科技树（研究入口从顶部导航移到这里）。

> **科技卡**：每张科技卡除一句描述外，固定显示「作用」列表，逐条列出该科技解锁的工作 / 资源 / 升级项 / 数值加成，不只显示风味描述。

> **采矿是例外**：13 种矿石 = 13 条独立配方，按解锁科技逐步出现；周期 = 3 秒 × 100 / 权重（权重越高越快），不再"按权重随机抽 1 种"。

从上到下五段：

1. **技能头**：工作图标 + 名称（+「角色特技」/「⚡ N 瓦」徽章，**不标时代**）+ **一句话简介（只写做什么，不写"2 秒 1 木材 = 30/分钟"这类产能算式）** + 「N 人在工作」。
2. **可用角色列表**：所有角色头像横向排列，**头像右下角显示他当前在做的工作图标**（闲置的不显示角标），正在做这份工作的头像描边变绿；超过人口上限的不显示在其中。
3. **项目网格**：**每个项目一张卡，各自带独立的入驻槽、产出图标、进度条与精通经验条**。**整张项目卡都是拖入点**，把角色头像拖到卡片任意位置即可入驻；**点整张卡**：空置时弹出与入驻槽相同的**下拉菜单**（不再用全屏弹窗），已有人时**直接撤下**该角色；点卡片右上角的入驻槽**永远弹菜单**（换人 / 撤下），不会被"直接撤下"挡住。同一角色只能占一个槽，换槽会自动离开原槽。**不再有"整份工作共用一个入驻槽"，也没有"点卡片切换配方"**。
4. **卡片数值**：产出 / 消耗（**消耗栏里库存不够的那一项，物品名标红**；整卡缺料时卡片底部另给「材料不足」）、周期（受升级项 / 舒适度 / 精通 / 角色加成影响）、入驻者与精通等级；**每帧只更新进度条与精通条，不重建 DOM**。
5. **升级项卡片**：每档一张（效果、耗电、所需材料与当前库存），够了就能买；**已购的档位只留「已购」徽章与效果，不再列材料、也没有购买按钮**；**未满足「解锁条件」、上一档未购（链式升级）或「持有 ≥30% 所需资源」的档位根本不出现** —— 不是置灰，也不是写「？？？」（规则见 `科技树.md「设计原则」`）。

### 5.1 五个区块

> 中间那一列 = **夹在装备栏与战斗属性之间**的那块，不是单独一行。

| 区块 | 位置 | 内容 | 交互 |
|---|---|---|---|
| **左** | 第 1 列 | **选中角色的头像**，**12 个装备栏环绕在头像周围** | 点装备栏可卸下；从中间拖装备过来即穿上 |
| **中** | 第 2 列（装备栏 ↔ 战斗属性之间）| **仓库里可用的装备**（只显示该角色能穿 / 能拿的）；**网格排列：先横后竖，每行几个随列宽自适应**（见 §5.2）| 拖到装备栏 = 换装；拖回中间 = 卸下 |
| **右上** | 第 3 列上半 | **战斗属性**（生命 / 命中 / 力量 / 防御 / 伤害减免 / 攻击间隔，照 `战斗系统.md「角色战斗属性」`）| 只读 |
| **右下** | 第 3 列下半（**战斗属性正下方**）| **精通小窗** —— 列出该角色**所有工作的精通等级 + 精通经验** | **高度自适应（clamp 120~320 px，跟窗口高度走）+ 内部滚动条**；技能书有 31 本，不设滚动会撑爆整个页面。**整页每 1.5 秒重绘一次，重绘后内层滚动位置保持**（`UI._saveScroll()` / `_restoreScroll()` 按 DOM 路径记录 `scrollTop`），不会跳回顶部 |
| **下方** | 整宽一行 | **角色列表，头像排列** | **拖拽排序**，决定上场顺位 |

- **随机普通角色的「开除」**：选中一名随机普通角色时，详情区（有名英雄显示「🎁 送礼物」的位置）显示红色**「开除」**按钮 → 弹二次确认框（写明「永久消失、装备退回仓库」）→ 确认后角色从存档 / 角色列表 / 所有岗位移除，身上装备全部 `addItem` 回仓库。**有名英雄与玩家角色没有这个按钮**（`dismissChar` 会拒绝）。
- **双手武器占用副手**：主手是双手武器时，副手槽不显示空槽，而是**半透明显示主手武器**（`.slot.ghost`，40% 左右透明度 + 虚线边），悬停可看武器面板；点击它仍打开副手装备列表。选择副手装备会自动把双手武器退回仓库并提示，反向装备双手武器时副手也会自动退回。
- **一键最优**：按「主手 + 副手合计战力」比较 1H+副手与 2H 两种组合，再逐栏补最好装备；仓库里的未知 / 运行时物品会被跳过，不会让按钮点不动。

### 5.2 中间列的装备怎么排：先横后竖 + 列数自适应

- **先横后竖**：横向排满一行再换下一行，**不是单列竖排**。
- **每行几个不写死**：格子有最小尺寸，**容器多宽就自动排几个** —— 窗口拉宽一行更多，缩窄一行更少。
- 容器**高度自适应**（与左侧装备栏那一行同高），超出部分**竖向滚动条**。


### 5.3 布局与响应式（全自适应，不写死尺寸）

> **不写死尺寸，界面随屏幕 / 窗口调整。** 下面只写**要达成什么效果**，具体怎么实现交给实装时决定。

| 项 | 要什么效果 |
|---|---|
| **页面宽度** | **铺满窗口**，只留少量外边距；超宽屏给一个**宽松上限**，防止内容拉成面条 —— 不做固定窄栏 |
| **三列宽度** | 左 / 中 / 右**按比例分配**，跟着窗口一起变，**不写死** |
| **仓库格（中列）** | **列数随容器宽度自动增减**，先横后竖；格子有最小尺寸，放不下就换列 |
| **角色格（下方）** | 同一套规则，**格子比装备格大一圈**（头像要看得清）|
| **装备栏环绕（左列）** | 头像为锚点，12 个槽位绕一圈；**槽位碰到容器边缘就换行**（不做强制单圈）|
| **右列纵向分配** | 上半 = 战斗属性（高度随内容）；下半 = 精通小窗（**高度跟窗口走、有上限、内部滚动**）—— 两者之间用分隔线 |
| **下方角色列表高度** | **跟窗口高度走、有上限、超出滚动**，窗口越高看得越多 |
| **窄屏** | 窄到一定程度，三列**竖排堆叠成单列**（左 → 中 → 右 → 下方列表）；**不单独做一套移动端布局**，靠同一套规则自然降级 |
| **不做筛选** | 角色页面**只跟「拖拽排列」有关**，不做按职业 / 在岗 / 好感度的筛选 |

## 六、角色上限与上场机制

角色上限由**住房**决定：初始 **5** 人，6 档住房依次 7 / 9 / 11 / 13 / 15 / **18**，住满即满编（18 是绝对硬顶，没有别的系统能加人数；也**没有舒适度门槛**）；角色列表**前 X 名可上场**（X = 角色上限），第 X+1 名起头像**置灰**、不可上场、不可被任何工作选中；**拖拽是唯一的上场操作**，被拖进置灰区的角色**自动退出工作**。

完整规则（含待命队列的权利与义务、`[潜水摸鱼]` 豁免）→ `被动.md「角色上限与上场机制」`。

## 七、离线结算弹窗

启动时若结算了离线收益（离开 ≥ 60 秒），在游戏界面就绪后弹一次「🌙 离线结算」，**只弹一次、不打断新手三步引导**（有离线结算时跳过 tips）。

| 区块 | 内容 |
|---|---|
| **标题行** | 离开了多久、实际按多久结算；超过 8 小时标注「离线收益上限 8 小时」 |
| **收益卡** | 产出按价值取前 10 种（图标 + 名称 + 数量），金币 / 科研点 / 击杀数各一行；无产出时提示「还有工作没派人？」 |
| **精通卡** | 离线期间升级的「角色 × 工作」精通等级变化（最多 6 项，`📘 角色 · 工作 Lv0 → 36`）；超过 6 项折叠为「另有 N 项」；没有升级则不显示 |
| **损耗卡** | 粮仓从 X → Y（下降才显示）、消耗前 4 种、袭击次数与「全部击退 / 失守 N 次」 |
| **重伤卡** | 离线期间被打成重伤的角色名单（红色） |
| **按钮** | 「收下」关闭 |

数据来自 Engine.settleOffline(awaySec) 返回的结算报告，弹窗只负责展示，不重复结算。

**后台标签页**：`document.hidden` 期间跳过 gameTick、不逐跳推进（浏览器会把定时器节流到 1 次/分钟，边走边算每跳只有 60 秒，永远够不到 2 分钟的弹窗阈值）；回到前台由 `visibilitychange` 立刻按真实离开时长补一次结算，≥2 分钟照常弹「🌙 离线结算」，<60 秒仍按 0.2 秒小步追帧。

## 八、物品悬浮面板（v0.0.14）

任何带 `data-tip-item="<物品id>"` 的元素，鼠标悬停时弹出**统一的物品面板**（`#itemTip`），离开即收；面板本身 `pointer-events:none`，不会挡住点击。

| 挂锚点的位置 | 说明 |
|---|---|
| **图鉴 · 物品卡** | 只给**已收录**的卡片挂锚点；未收录（？？？）不给，避免剧透 |
| **工作页 · 物品类项目卡** | 卡片的第一个可解析产物是物品时，整张卡可悬停；**入驻槽（`data-act="recslot"`）不触发**，鼠标在槽上时收面板 |
| **工作页 · 产出 / 消耗徽章** | `ioList` 的每个徽章都是「物品图标 + 名称 ×数量」，并各自挂锚点；**消耗栏**（`ioList(inputs, true)`）里库存不够的物品名用 `<span class="red">` 标红，产出栏不检查库存 |
| **仓库 / 粮仓行** | 物品名单元格 |
| **角色页 · 装备槽** | 已穿上装备的 12 个槽位，悬停看该物品的完整面板；**空槽只保留原生提示**（「头盔（空）」），不挂锚点 |
| **角色页 · 仓库装备格** | 中间「仓库装备」里的每一件都可悬停（原本的 `title` 原生提示已去掉，避免双份提示） |
| **商店 · 货架 / 常驻商品卡** | **所有商品**都挂锚点：货架 6 格（含英雄碎片）、升星药水、已解锁工作的精通书 |

**显示内容**（`UI.itemTipHtml()`，数据只来自两处文件）

| 区块 | 内容 |
|---|---|
| 头部 | 物品图标、名称、**时代** / 分类 / 槽位 / 双手 徽章 |
| 战斗数值（仅 60 装备 + 29 武器） | 伤害减免、力量、命中、攻击间隔、射程、保暖、护盾、破甲、无视减免、暴击、特性文本、**战力贡献**（武器 力量×2+命中；防具 减免×5+力量×2，与 `Engine.gearPower` 同权重） |
| 经济 | 卖出价、买入价（有 `buy` 固定价时优先用它）；**星尘兑换品显示「兑换价 N 星尘」**，星尘本身不显示买入价；持有件数、总价值 |
| 类别专属 | 技能书 → 对应工作精通 +10 级；抽卡品 → 类别；礼物 → 好感值；粮仓品 → 腐坏速率 |
| 获取 / 用途 / 备注 | `src` / `use` / `note` 文本 |
| 造价 | 每种材料「图标 + 名称 ×数量」，**数量不足标红** |
| 页脚 | 是否已收录图鉴 |

- **武器数值以 `WEAPON_COMBAT` 为准**：`items.js` 只有 `str`，攻速 / 命中 / 射程 / 破甲 / 暴击在 `enemies.js` 的 `WEAPON_COMBAT`（按中文名索引）。取数顺序与 `Engine.charStats()` 一致，面板不会出现第二套数值。
- **时代属性在面板里可见**：`era` 不是装饰字段，它决定商店货架（只卖当前时代及更早）、装备走哪个工作台（石器 → 加工）、以及「石器/金属装备」升级项的筛选范围，因此保留并在此露出。
- **特性不重复数值**：`WEAPON_COMBAT.special` 里的「射程 2」「破甲 10%」「暴击 15%」「无视 30% 伤害减免」在面板上已经各自成行，`UI.tipSpecial()` 会把这类片段剥掉；剥完为空就整行不显示（短弓、长弓、石矛、石斧、双手剑、巨锤等），只留「火器」「高频」「高命中」这类真正额外的信息。
- **重绘后跟随**：整页每 1.5 秒 `innerHTML` 重绘一次，锚点元素会被替换。`UI.syncTip()` 在每次 `render()` 末尾用最后一次指针坐标 `elementFromPoint` 找回锚点，找回失败才收起面板（不会 1.5 秒闪断）。
- **定位锚在元素上，不跟鼠标**：默认贴在悬停元素**正下方居中（间距 8px）**；下方放不下就翻到**正上方**；上下都不够时贴视口底/顶（可能轻微压住锚点）。横向越界自动夹进视口。战斗数值与经济各用**两列网格**排，面板高度约 300px，页面中部的卡片基本都能完整显示在下方。
- 样式见 `#itemTip`（`css/style.css`），弹出动画只做透明度（不做位移，避免测量时位置抖动）。

### 8.1 页面文案从简（v0.0.21）

页面上的说明只回答「这块是干什么的」，**不写具体数值、公式、概率与保底规则**；精确数值交给徽章、卡片与悬浮面板。当前口径：

| 页面 | 文案 |
|---|---|
| 住所与娱乐 | 「住房能提高角色上限，使有效角色更多。」（不写初始 5 人 / 住满 18 人 / 每档人数） |
| 防御 | 「每隔一段时间会有袭击发生，基地战力过低会丢失部分财物。」（不写 2 小时 / 各抢 10%） |
| 商店 | **不写买入价规则与第 6 格说明**；升星药水与精通书直接用带图标的卡片常驻展示，不再用长句解释来源 |
| 招募 | 只留一句「消耗英雄碎片招募。可能抽到角色，也可能抽到好感度礼物。」；**不显示保底计数**，也不写概率与「无限生成 / 每次都是新的」 |
| 电力 / 科技 / 狩猎 / 仓库 | 各留一句作用说明；电价、配方、认知度加成等细节留在卡片与面板里 |

## 九、物品 / 敌人图标（v0.0.18）

全游戏不再用 emoji 当物品图，改为**程序化内联 SVG**：`js/icons.js` 里一张规格表 + 一个形状库，按 id 生成 48×48 的图标字符串，直接拼进 `innerHTML`。

### 9.1 为什么不用图片

| 方案 | 问题 |
|---|---|
| PNG / 精灵图 | 212 件物品 + 26 种敌人要切 238 张图，改色 / 换主题都要重做，仓库体积大，还得处理 `@2x` |
| AI 生图 | 每件物品风格不收敛，小尺寸糊成一团，且无法随主题调色 |
| **程序化 SVG（采用）** | 零图片请求、确定性输出（同一 id 永远同一张图）、改一个调色板就能整体换色、任意尺寸都清晰 |

### 9.2 视觉规范（照梅尔沃放置的厚重手绘感）

- **画布 48×48**，物体大致占 `6…42`，底部留 3~6px 给接地阴影；四周留 2px 防描边被裁。
- **统一描边** `#241b13`，线宽 1.7（小件 1.1~1.4，轮廓件 2.0~2.6）；描边**不随主题变**，浅色主题下图标仍是暖黑边。
- **三阶平涂**：每个调色板给 `l / m / d` 三档（亮面 / 主色 / 暗面），最多加一种点缀色（金属高光、火焰、能量）。**不用渐变、不用 `<defs>`/`id`**（同一页面会重复出现同一图标，重复 id 会让 `url(#…)` 全部指向第一个）。
- **接地阴影**：落地类物品（矿石、锭、装备、动物）底部一层淡椭圆；悬挂类（羽毛、药水）不加。
- 敌人统一**朝左**、四足/人形站在同一条基线上，方便在列表里对齐。

### 9.3 接口

```js
ICONS.item(it | id)      // 物品对象或 id → '<svg class="icSvg" viewBox="0 0 48 48">…</svg>'（带缓存）
ICONS.enemy(e | id | 中文名)  // 敌人，同上
ICONS.job(j | 工作id)    // 33 份工作（jobs.js 的 id）
ICONS.passive(中文名 | 被动对象)  // 住房 / 舒适度 / 工事，按 passives.js 的 name 索引
ICONS.nav('housing' | 'defense' | 'shop' | 'characters' | 'codex' | 'recruit' | 'warehouse')
ICONS.SPEC / ICONS.ENEMY_SPEC / ICONS.PASS_SPEC  // 规格表
ICONS.PAL / ICONS.SH / ICONS.JOB_SH / ICONS.PASS_SH / ICONS.NAV_SH  // 调色板 / 形状库
ICONS.missing()          // 缺形状清单（含 J:/P:/N: 前缀），测试里断言为空
```

- **接入口只有两处**：`UI.itemIcon(it)`（原来是 emoji 映射）、`UI.enemyIcon(e, cls)`；工作与被动再各一个：`UI.jobIcon(job)`、`UI.passIcon(name, small)`。所有页面都走这几个函数，所以换图标不需要改 15 个调用点。
- **加载顺序**：`icons.js` 必须在 `ui.js` 之前、`engine.js` 之后（要用 `window.ITEMS` / `window.JOBS` / `window.HOUSING` 等）。
- **敌人立绘**：狩猎页战场（72px 圆角底 + 66px 图）、「本区域敌人物种」徽章（25px）、图鉴敌人表（25px）。**未收录的敌人只显示「？？？」，不给图标**，避免剧透。
- **工作图标出现的位置**：左侧栏（17px）、工作页标题（52px）、项目卡右上角标（18px）、角色特技导航。
- **被动图标出现的位置**：住所与娱乐页的住房卡与舒适度卡、防御页的工事卡（24px，舒适度用 20px）、左侧栏 7 个导航入口。

### 9.4 加一件新物品 / 新敌人

1. 在 `js/data/items.js` 里加条目（照旧）。
2. 在 `js/icons.js` 的 `SPEC` 里加一行 `物品id: ['形状名', '调色板key', '附属']`。
3. 形状能复用就直接填（如 `['ingot','gold']`），不能复用就在 `SH` 里加一个函数：`SH.名字 = (c, r, acc) => 若干 sil/det/ln 调用的字符串`。
   - `c` 是主调色板（`c.l/c.m/c.d`），`r` 是**按 id 播种的稳定随机**（同一物品每次抖动一致），`acc` 是附属（多是第二个调色板 key）。
4. 跑 `node tools/test.js`（会断言 `ICONS.missing()` 为空）和 `node tools/icon-shot.mjs <from> <to>` 目检。

### 9.5 校对工具

| 工具 | 用途 |
|---|---|
| `tools/icon-sheet.html` | 浏览器直接打开：按 `ITEM_ORDER` 铺满全部图标，每格同时给 52px 和 18px 两种尺寸 + 名称 / id，专门用来抓「大图还行、小图像一坨」的问题。支持 `?from=0&to=60` 切片、`?ids=stone,copper_ore` 单看几件、`?all=1` 连隐藏敌人一起看 |
| `tools/icon-shot.mjs` | 用 Edge headless + CDP 把上面那页截图到 `%TEMP%\era-icons\`，方便逐格看 |
| `tools/shot-ui.mjs` | 开着 `?demo` 局把仓库 / 狩猎 / 图鉴等真实页面截图，确认图标在槽位、徽章、表格里的实际尺寸 |

### 9.6 已知取舍

- 图标是**纯字符串拼接**，没有 DOM 依赖，`node` 里能直接 `eval` 后渲染（测试就是这么做的）。
- 形状函数里不做碰撞检测，复杂件靠**手动调坐标**；改形状后必须截图目检，`test.js` 只能保证「不报错、不缺规格」。
- 同色系小件（石头 / 铜矿 / 石灰石）在 20px 下仍会略糊，靠**轮廓差异**（矿块数量、色相、点缀）区分，不靠细节。

### 9.7 工作 / 被动图标（v0.0.19）

- **工作 = 动词，被动 = 名词**：33 份工作一律画「工具 + 材料」的动作场景（伐木是斧头剁进圆木、熔炼是砖炉冒火、粒子对撞是原子轨道），被动一律画「成品本身」（住房画房子、舒适度画家具 / 地板、工事画墙体 / 炮塔），这样工作页和被动页在视觉上不会混。
- **住房按档位递进**：茅草棚（茅草顶 + 泥墙）→ 长屋（长脊 + 木梁）→ 石屋（石墙 + 红瓦）→ 公寓（多层窗格）→ 住宅区（三栋高低错落）→ 殖民舱（胶囊 + 舷窗），一眼能看出「升级了」。
- **三种地板靠投影区分**：木地板暖棕、石地板冷灰、瓷砖地板浅蓝灰 + 明显砖缝，都在同一套等轴测菱形里画，摆在一起像同一个房间的地面。
- **规格表按中文名索引**：住房 / 舒适度 / 工事在 `passives.js` 里没有 id，只有 `name`，所以 `PASS_SPEC` 用中文名做键（`'石墙': 'stonewall'`），改名会退回木箱兜底，`test.js` 会报出来。
- **导航图标单独一组**：`NAV_SH` 只服务左侧栏那 7 个入口，尺寸固定 17px，和页面内容图标不是一个量级。
